## Возраст 13–18: не одна универсальная галочка

[Ст.28 ГК РФ](https://www.consultant.ru/document/cons_doc_LAW_5142/cc856395792cdd3ebdb55d49f5f2f9b8d6cabced/) регулирует сделки до 14 лет через представителей с указанными исключениями. [Ст.26](https://www.consultant.ru/document/cons_doc_LAW_5142/7b6abd47219e2aa6081ac21b41e9e83d80fb45df/) различает сделки 14–18 лет с согласием представителей и самостоятельные действия. Эти нормы нельзя превращать в утверждение «после 14 любые ПД разрешены без родителей» или «152-ФЗ всегда требует бумажное согласие родителей до 18».

**Рекомендация до пилота:** согласовать с юристом/оператором схему договора и основания обработки по возрастным группам: 13; 14–17; 18 и случаи полной дееспособности. Там, где требуется представитель, определить способ подтверждения полномочий и доказательства, не собирать копии паспортов в учебный кабинет по умолчанию. Поля и документы для этого добавляются только после определения необходимого состава. Родительский кабинет для такой процедуры не обязателен.

Фото тетради могут содержать имя, школу, лицо и EXIF с местоположением. Не обещать анонимность по username; аккаунт связан с преподавателем и историей. Фото не автоматически биометрические ПД: значение имеет цель использования для установления личности; не внедрять распознавание лиц.

| Курсы, расписание, ответы, оценки | Учебный процесс | Только свой участник/владелец курса; админ по функции |

| Security/audit logs | Защита и разбор действий | Не писать bodies/токены; ротация и ограниченный доступ |
| Основание/подтверждение представительства | Правомерность доступа | Отдельный защищённый реестр, минимальный proof reference и версия документа; не в Git |

Срок хранения учебного архива, логов, доказательств и backup не утверждён. До P01 — synthetic; до реальных данных оператор утверждает таблицу «цель → основание → состав → срок → удаление → ответственный». Retention backup не должен незаметно возвращать удалённые данные: deletion ledger применяется при восстановлении; доступ к старым копиям ограничен.

## P01: критерий готовности к реальным пользователям

- [ ] Определён оператор и контакты; определены отношения с преподавателями и провайдерами обработки.
- [ ] Проверена актуальная редакция норм и выполнено требуемое уведомление/документировано исключение.
- [ ] Утверждены основания, возрастные сценарии, документы и способ доказательства полномочий.
- [ ] Политика опубликована, запросы доступа/исправления/отзыва/удаления имеют рабочий процесс.
- [ ] Подтверждены регионы БД/media/backups и перечень внешних потоков; сторонняя аналитика по умолчанию отсутствует.
- [ ] Определены применимые меры защиты и ответственные; выполнены тесты прав/файлов, восстановление, процедура инцидента.
- [ ] Установлены сроки хранения и механизм удаления; ограничения архива объяснены пользователям.

Реальные данные учеников и production dumps не отправлять в Codex, GitHub, скриншоты CI или внешние навыки. Для разработки достаточно синтетических двух преподавателей, общего ученика и второго ученика. ВК-интеграцию и коммерческое SaaS расширение проверять отдельно при изменении потоков данных.
