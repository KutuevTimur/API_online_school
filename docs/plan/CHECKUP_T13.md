## Найденные дефекты — сначала исправить

### Q01 — P1: имя загружаемого аватара позволяет затронуть файл другого пользователя

Место: `src/modules/handlers_files/converter_images.py:85–95,163–166`; обработчик используется в пользовательских и курсовых аватарах. Имя клиента вставляется в имя временного файла, затем `.resolve()` нормализует `..` без проверки принадлежности temp. Запись и finally-unlink выполняются уже по вышедшему за temp пути.

**Воспроизведено через настоящий ASGI API с fixture на guarded PostgreSQL и исключительно временными media:** teacher загружает собственный аватар через `PATCH /users/{свой user_id}/avatar`; filename указывает через `/../../avatars_users/{другой user_id}/avatar.webp` на файл synthetic ученика. Невалидное изображение корректно получает 400, но файл ученика уже удалён. Никакие реальные пользовательские файлы или dev media в этой пробе не использовались. Та же ошибка отдельно подтверждена прямым вызовом handler в TemporaryDirectory.

Почему текущие тесты пропустили: object permissions проверяют URL user_id, но не влияние multipart filename на filesystem. Безопасный LocalStorage T12 защищает учебные документы, старый avatar converter его не использует.

Исправление: temp key генерируется исключительно сервером; оригинальное имя не участвует в пути. Использовать существующие safe storage primitives, ограниченный декодер и проверку содержимого. Тестировать traversal, абсолютные/Windows имена, symlink; при любом отказе все чужие файлы неизменны. До исправления не открывать этот API реальным пользователям/в интернет.

### Q02 — P2: неудачная замена удаляет прежний аватар

Место: `src/modules/users/service.py:231–236`, `src/modules/courses/service.py:256–261`. Сначала удаляется прежний файл, потом валидируется/создаётся новый. Повреждённая картинка или ошибка конвертации оставляет пользователя/курс без старого файла, хотя операция не завершилась.

**Воспроизведено для обоих сервисов** в изолированных TemporaryDirectory: прежний файл существует → `_create_avatar` подменён на ожидаемый отказ → после отказа прежнего файла нет. Проверка авторизации подменена только в этой unit-пробе для изоляции последовательности файловых операций; проблема Q01 подтверждена отдельно без подмены auth через API.

Исправление: новое immutable имя, validate/normalize → commit новой ссылки → удаление старого с повтором. Ошибка до commit сохраняет старый файл и указатель. Обновить `avatar_file`, сейчас он вычисляет фиксированное `avatar.webp`, если новая реализация хранит opaque key. При `remove_avatar` не превращать повторное удаление отсутствующего файла в ошибку после уже выполненного commit. Проверить аудит admin при rollback.

### Q03 — P2: удаление ДЗ с черновиком даёт HTTP 500

Место: `src/modules/homeworks/service.py:205–215`, `src/modules/homeworks/repository.py:66–68`, FK `HomeworkSubmission.homework_id` без ON DELETE CASCADE. Сервис запрещает удаление checked, но разрешает попытку bulk DELETE при draft/submitted. ORM cascade на relationship при таком DELETE не выполняется.

**Воспроизведено на PostgreSQL через API:** fixture создаёт ДЗ с рабочим draft и файлом → владелец teacher вызывает DELETE ДЗ с корректными lesson_id/student_user_id → наружу выходит IntegrityError/ForeignKeyViolation, что соответствует HTTP 500 в реальном сервере. Старый тест удаления ДЗ создаёт работу без ответов; тест T11 закрывает только checked.

Рекомендуемый минимальный безопасный контракт для T13R: если есть хоть одна попытка/исторический ответ, вернуть 409 с понятной причиной и сохранить всё; не вводить каскадное уничтожение истории без отдельного продуктового решения. ДЗ без ответов можно удалять с прежней очисткой файлов/placements. Это рекомендация исправления, не приписываемое владельцу новое согласование. При выборе другой семантики сначала явно решить вопрос сохранения ответов.

### Q04 — P2: PATCH курса принимает null для обязательных полей и доходит до ошибки БД

Место: `src/modules/courses/models_dto.py:79–87`, `src/modules/courses/service.py:update_course`. Optional в PATCH смешивает «поле не прислали» и «поле прислали null»; exclude_unset оставляет явный null. Колонки name/slug/avatar_type/is_deleted не nullable.

**Воспроизведено на PostgreSQL через API:** PATCH своего курса `{ "name": null }` → unhandled NOT NULL IntegrityError, вместо 422. В Lesson DTO уже есть нужный образец non-null validator; в Course его нет.

Исправление: omission допустим, явный null для обязательных полей → 422 до SQL; description/call_url по-прежнему можно очищать null. Проверить ограничения длины name/slug и конфликты slug; не заменить реальные ошибки универсальным подавлением исключений БД.
