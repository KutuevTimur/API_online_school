## Использование

Обычное «продолжай одну следующую задачу» в новом локальном чате LGG:
AGENTS → STATUS → актуальный subsection карточки → работа по экономному режиму.
«Проведи глубокий аудит и выполни обоснованную локальную оптимизацию» включает
режим WORKFLOW. Границы безопасности/ручной приёмки/Git сохраняются.
Конфигурация доверенного проекта загружается клиентом; выбор момента делегирования
и соблюдение бюджета контекста остаются инструкциями модели. Существующие сессии
и явный UI выбор могут сохранять собственные параметры. Недоступный worker/model →
основной выполняет задачу сам без скрытых API расходов.

Commit/push/deploy: не выполнялись. Следующий продуктовый шаг остаётся T15b.3 VERIFY.

## Ошибки T15b.4 и минимальный расход · 21.10.2026

Владелец потребовал фиксировать ошибки и минимизировать дальнейший расход.
Прежний следующий продуктовый шаг выше — история; актуальный факт в STATUS.
- Ошибки исполнителя: большие обрезанные чтения/повтор контекста, путаница
  root/frontend cwd, угаданные HTTP-код/redirect и путь отсутствующего скрипта;
  зависимые команды продолжались после ошибки. Это вызвало лишние повторы.
- Подготовка browser fixture не учла остаточные suite данные; новый PostgreSQL
  проверялся до readiness. Сохранность исходного preview при этом обеспечена.
- Один worker Luna/high делал frontend; общая экономия токенов не измерялась
  и не доказана. Повторы увеличили расход. Backend499,91s/migrations83,36s —
  часть длительности, не метрика токенов. Бенчмарки ради оценки не запускать.
- AGENTS: выполнение самому по умолчанию; worker только при конкретной ожидаемой
  экономии, узкие чтения, проверка путей/контрактов, остановка после ошибки,
  readiness/fixture заранее, scoped проверки и один финальный дорогой gate.
  Обязательные проверки безопасности/сохранности/карточки сохраняются.
- Передача была неполной: URL без удобных входов вызвал лишний запрос. Сразу
  давать путь к приватным входам; по явному запросу — проверенные synthetic входы.
  Пароли не копировать в инструкции/журналы.
- Эта правка только документационная: сверка правил/diff; без продуктовых
  tests/DB/browser, смены config/моделей, commit/push/deploy/установок.
