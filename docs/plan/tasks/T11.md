## Контракт и события

| Событие | Ожидаемый срок |
|---|---|
| ДЗ в уроке 19 октября, следующего нет | null, «До следующего занятия» |
| Создан урок 22 октября того же ученика/курса | 22 октября |
| Вставлен урок 21 октября | 21 октября, прежнее в журнале |
| Следующая встреча перенесена на 23 октября | 23 октября либо более ранний допустимый кандидат |
| Следующий урок отменён/архивирован | следующий допустимый либо null |
| Время прошло, урок completed | прежний срок, now ничего не сдвигает |
| Долг в уроке 22 октября, следующий 26 октября | в основном списке 26 октября, исходный срок в истории |
| Checked | все placement сроки и последняя привязка зафиксированы |

Долг не копирует ответ/файлы и не создаёт второй элемент очереди проверки.
Только тот же курс/ученик, новая placement позже текущей по (scheduled_at,id),
повтор пары идемпотентен; циклов ссылок нет (FK только на Homework).

## Реализация

homework_placements: unique(homework_id,lesson_student_id), один original (partial unique),
kind original/debt, due_lesson_id/due_at nullable (новый расчёт — парой, импортированный исторический ручной срок без выдуманного FK), created_at.
homework_deadline_events: append-only снимки срока и причины.
Homework.deadline — nullable effective cache; deadline_frozen_at — фиксация checked.
Миграция сохраняет старый ручной deadline в legacy_import, затем рассчитывает
автоматический срок активных непроверенных работ; checked и read-only сохраняют прежний срок. Кандидаты исключают grants из разрыва участия.
Курс блокируется прежде Homework/Submission: единый порядок с T09/T10.
API: POST /homeworks/{id}/debts {lesson_id}, GET /homeworks/{id}/placements;
GET /homeworks — placement данного урока, /my — одна работа с последней видимой placement.
Публичная ручная установка deadline исключена, передача поля возвращает 422.

## API и исторические данные

- `POST /homeworks`: multipart `lesson_id`, `student_user_id`, `title`, опциональные
  `description`/`file`. `deadline` больше не принимается (422); это намеренное
  изменение прежнего ручного контракта по D04. Ответ содержит nullable deadline,
  due_lesson_id, placement_id, placement_kind, placement_lesson_id, submission_status и deadline_frozen_at.
- `POST /homeworks/{id}/debts` JSON `{ "lesson_id": <поздний урок> }`: только свой
  teacher, обе стороны write-доступны, тот же курс/ученик, origin/current раньше
  target по `(scheduled_at,id)`. Повтор пары возвращает ту же placement с 201.
  Checked → 409. Student/admin → 403, чужой объект → 404.
- `GET /homeworks/{id}/placements`: original/debt и упорядоченные снимки сроков
  с причинами assigned/debt_added/lesson_created/lesson_updated/lesson_archived/
  lesson_restored/course_restored/recipient_added/recipient_removed/
  enrollment_restored/teacher_link_restored/checked.
  Legacy: legacy_import и migration_recalculated. Пользователь не меняет журнал.
- `GET /homeworks?lesson_id=…&student_user_id=…`: работа с placement именно этого
  урока. `/homeworks/my`: один Homework, последняя доступная placement.
  `submission_status=submitted` означает «ожидает проверки». Новой копии ответа,
  файлов или элемента review queue нет. File URL допустим с origin или debt lesson,
  но проверяет доступ к обоим объектам. У lesson.has_homework учитываются долги.
- Пересчёт атомарен с изменением расписания; Course → Lesson/enrollment → Homework →
  Submission, блокировка курса сериализует перенос-vs-check и конкурентный debt.
  Архив/закрытое участие read-only; скрытые grants в EnrollmentGap не кандидаты.
  Снимки журнала фильтруются по cutoff/gaps; невидимая debt не меняет student response.
  Возврат участия/связи пересчитывает активные сроки; закрытая история до возврата
  неизменна. Teacher relink берёт курсы по ID до link/enrollment locks. Runtime events
  используют wall-clock UTC после возврата доступа, а не начало SQL-транзакции внутри gap.
- Migration `689ceabc2b0c` создана autogenerate и дополнена data backfill.
  Оригинальная placement на каждую прежнюю Homework, legacy_import сохраняет ручной
  срок. У active непроверенной работы — новый расчёт; у checked/закрытой истории —
  прежний ручной срок (due_lesson_id=null, без выдуманной связи). Старая оценка,
  ответ и файлы сохраняются. Для pristine backfill downgrade возвращает ручные
  сроки; при новых placements/events/проверках отказывает до потери истории.
- Purge курса удаляет placements/events через FK cascade в той же транзакции;
  чужой курс/файл остаются. Обычное удаление checked Homework закрыто (403),
  чтобы не обойти immutable history удалением родителя.
