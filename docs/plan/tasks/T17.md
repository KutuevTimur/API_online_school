## T17.1 — локальный release candidate на synthetic стенде

Production compose отдельно от dev/test: proxy static frontend и /api rewrite,
SPA fallback deep routes, HTTPS-ready config, API/private media/DB внутренние,
DB port не exposed. Один API instance для начала, maintenance worker не дублируется
случайно несколькими процессами. Не добавлять Redis/Celery/Kubernetes.
Pinned base images/digests, Node build-only, non-root API, minimal image, no reload,
graceful SIGTERM, readiness DB/dependencies и отдельная liveness без конфигурации.
Writable media/temp volume явные; no `.env/.git/.venv/dumps/dev credentials` в image.
Proxy upload/time limits согласованы с API20MiB/102MiB request ceiling и 30s/file;
bulk request frontend по 1file, всё равно не отрезать легитимный API случайным 1MiB.
Production cookie Secure/Path/origin, CSP local fonts/worker/blob images только
нужные, no public media mount, error logs без request bodies/tokens.
Migration отдельным one-shot job, revision current/head preflight; никакого
metadata.create_all/recreate_test_db в production startup.

Приёмка: build immutable release SHA, состав images/scans/license, cold boot и
restart сохраняют DB/media; deep UI URL и /api404 не смешиваются; authenticated
Range/download, WebP/HEIC, CSRF/two tabs, guarded smoke на production-mode synthetic
конфиге. Неверная production origin/secret/cookie config fail-fast. npm build,
backend integration, compose config и health/stop tests по необходимости.
Ручная приёмка: открыть локальный release stand URL (агент задаёт свободный loopback
port и сообщает фактический), пройти login→PDF→upload→review; честно «ещё локально».
Риски: proxy path/cookie path mismatch, media volume потерян, image secret leak.

## T17.2 — подготовка конкретного Timeweb окружения

Зависимость .1 и ответ D09 **перед этим шагом**. Агент сначала проверяет имеющиеся
ENVIRONMENT/config, затем просит только недостающие несекретные сведения:
VPS/cloud/shared, ОС/архитектура, регион, свободные RAM/disk, уже запущенные сервисы,
домен/DNS, доступный backup destination. Рекомендуемый вариант — текущий VPS,
один isolated compose project без переустановки ОС; если shared hosting не подходит,
обосновать конкретное ограничение перед покупкой. Цены/SLA тогда сверить официально.
Адаптировать runbook, firewall80/443/SSH policy, TLS renewal, start/stop/log/rollback,
секреты в защищённом вводе. Никакого реального deploy/DNS write/покупки в T17.
Проверки: config dry-run/no secrets, review paths/ports/space и совместимости с
существующими приложениями. Ручная приёмка: владелец подтверждает параметры D09
и понимает где DB/media/backups; не обязан писать конфиги самостоятельно.
