## Выбранный путь

1. D00 unknown: работать только в созданной нами test DB. Не переписывать/удалять всю историю и не выполнять `alembic stamp head` вместо миграции.
2. В initial dev revision исправить **только исполнимость** `autcrement`→`autoincrement`. Это историческая коррекция сломанного DDL, явно документировать. Не переименовывать revision. Добавить следующую revision для согласования courses/student_courses с существующими soft-delete моделями, проверив все nullable/default/index/enum/FK расхождения, а не только два поля.
3. Existing `is_active` не автоматически равно `not is_deleted`: для synthetic dev baseline можно документировать mapping true→false / false→true после просмотра смысла. Для реальных строк mapping отдельно подтверждается read-only inventory и backup. Сначала add nullable, backfill, проверить counts, затем constraints; drop старого поля только после отсутствия читателей. `deleted_at` неизвестного старого события не выдавать за исторически точное время.
4. Empty DB: `alembic upgrade head`; сравнить SQLAlchemy metadata и inspector, включая нужные поля/индексы/constraints. Проверить повторный upgrade (no-op), откат последней новой revision на disposable DB и upgrade обратно. Downgrade не считается безопасным для production данных по одному тесту.
5. Synthetic database на initial dev revision: внести fixtures, upgrade новой revision, проверить идентичность PK, count и связей. Main revision — другой baseline: **не поддерживаем автоматический merge DB веток без данных и отдельного плана**. Обнаружение main revision при preflight должно закончиться понятным отказом, а не stamp/drop.
6. Запустить полный существующий pytest в изолированной БД; сохранить summary «passed/failed/skipped» и перечень реальных причин failures в `docs/plan/TEST_BASELINE.md`. Новые требования могут противоречить старым тестам; помечать несоответствие, не менять expectations лишь для зелени. Дефекты auth закрываются T03+, не скрывать xfail без причины.

- [x] Схема соответствует текущим ORM, неожиданный autogenerate diff отсутствует или каждое отличие объяснено.
- [x] Тестовый snapshot сохраняет строки/связи; unsupported main revision явно обозначена.
- [x] Baseline воспроизводим, все непройденные тесты перечислены с задачей исправления.

Риск: создание таблиц через Base.metadata.create_all в старых fixture скрывает поломанную Alembic-цепочку. Migration tests обязаны строить БД через Alembic. Full tests могут пока быть красными; T02 DONE допустим только если миграционные критерии проходят, а baseline failures имеют конкретные владельцы/ID и не препятствуют следующим auth regression tests.
