## Контракт и границы

- `UserRole.ADMIN`; через HTTP нельзя создать admin или повысить роль.
- `/auth/register`: teacher создаёт только нового student, профиль и собственную
  связь в одной транзакции; admin создаёт teacher/student. Создание student
  администратором само по себе не назначает преподавателя.
- Оба legacy `/auth/register_by_admin` и `/auth/register-by-admin` требуют bearer
  ADMIN. `password_for_admin` необязателен, игнорируется и не даёт полномочий.
- `POST /teacher_students`: только admin; body `teacher_user_id`,
  `student_user_id`; проверка ролей/профилей, идемпотентное назначение и
  восстановление завершённой связи. В ответе только user IDs и `active`.
- `teacher_students`: unique пары, started_at/ended_at, проверка порядка дат;
  отсутствие ended_at означает действующую связь. Завершение/архив — T07.
- `is_active` меняет только admin; teacher не редактирует аккаунт admin и его
  пароль через существующие account endpoints. Общая матрица объектов,
  ограничения списков/профилей/файлов остаются T06, invite/reset — T05b.
- Первый admin — интерактивный CLI, без пароля в аргументах/логах. Повтор
  возвращает «already exists» без изменений; advisory transaction lock
  предотвращает двух первых admin при одновременном запуске. Дополнительные
  admin не создаются этим bootstrap и через HTTP; отдельный режим вне T05.
