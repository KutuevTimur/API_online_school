## T15a.2 — решение, фото, отправка и результат

Зависимость .1. Файлы `features/homeworks/{api,queries,HomeworkListPage,
HomeworkPage,AnswerForm,SubmissionHistory}.*`, DraftProvider, e2e/student-answer.spec.ts.
Домашки todo/submitted/checked, course/view/overdue, сроки/долг/nullable due;
detail напрямую по homework_id. Working answer выбирается по is_working,
исторические попытки доступны отдельно и не редактируются.
Первое явное «Сохранить черновик» создаёт draft; дальше PATCH text с
expected_version form field; omission text отличается от очистки (текущее API
сохраняет текст по request.form наличие поля). Не создавать draft просто открытием.
3 фото +4-е append; точечные remove/replace; queue T14f, версии последовательно.
«Отправить решение»: save/append завершить, затем POST submit; partial failure
остаётся draft и объясняется. Submitted: «Сохранить изменения», checked read-only
с 0–5/comment рядом. У teacher новая version видна, повторного working ответа нет.
Просрочка сдаче не мешает. Deadline history /placements читается по запросу.

Приёмка: empty submit422, текст и/или файлы, добавление/замена не удаляет остальные,
submit retry не дублирует, checked immutable UI/server; draft edit-vs-check409
не теряет локальный текст. Quota/413/offline/timeout/re-auth same-user/logout
различимы. Проверить сохранение при cancel navigation, reload server draft,
предупреждение потери ещё не отправленных File. No browser persist secrets/content.
Real API E2E upload3→append4→remove1→submit→edit→teacher check fixture→read result;
version race с двумя sessions, slow request and resume; npm checks/audit.
Риск: неизвестный commit upload, ошибочный status «отправлено», stale cache.
Ручная приёмка ожидает: synthetic student самостоятельно открывает ДЗ, прикрепляет
3 synthetic фото, сохраняет draft, добавляет/убирает файл, отправляет, повторно
открывает. Объяснить volume persistence, не использовать фото реальных учеников.
Проверку teacher можно пока подготовить fixture; это честно обозначить.
Следующее T15a.3.
