# T14b — контекст, deep links и read-only API

Статус DONE локально (16.10.2026); зависимость T14a выполнена. Источники: PRODUCT §4–7, A04/A05/A11/A12, T11/T12.
Карточка исполнима без нового продуктового интервью. При необходимости разделить
сессию на read-context и conditional PATCH, сохранив этот ID и точный остаток.

Файлы: `homeworks`, `homework_placements`, `lectures`, `lessons`, `lesson_students`,
`courses`, `homework_submissions` DTO/views/services/repositories; check_permission;
file asset metadata через `files/service.py`; related PostgreSQL/ASGI tests.
Не менять бинарное хранение/нормализацию или правила попыток.

## Additive контракт

- GET `/homeworks/{homework_id}`: HomeworkResponse + `course_id`, `lesson_id`
  (origin), `student_user_id`, `teacher_user_id`, `course_name`, `lesson_title`,
  актуальная placement как сейчас, `working_submission_id?`, `access_mode`,
  `read_only_reason?`, `can_submit`, `can_review`, `can_manage`, `file?`.
  `access_mode=active|read_only`; причины course_archived/lesson_archived/
  enrollment_ended/access_expired/teacher_link_ended/history_only/role_read_only.
  Admin read-only учебного UI не равен архиву: view классифицирует доменное
  состояние, а can_manage/can_submit — разрешённое действие текущей роли.
  Флаг не заменяет авторизацию mutation; checked запрещает can_submit/can_review,
  но сам по себе не означает, что весь курс архивирован.
- Тот же context в новом `/homeworks/my/page` из T14a; можно отдельный subclass,
  не ломать старый array. Debt detail выбирает последнюю видимую placement, а для
  страницы урока существующий list использует placement данного урока. Для файла
  использовать видимый placement_lesson_id, а не невидимый origin.
- GET `/homeworks/available-debts?lesson_id=&student_user_id=&limit=20&offset=0`:
  page старых непроверенных Homework того же курса/ученика, существующий debt target
  помечен `already_added`, submitted помечен «На проверке». SQL scopes/COUNT прежде
  LIMIT; серверный POST debts по-прежнему окончательно валидирует T11.
- GET `/lessons/{lesson_id}/students`: page(limit20/offset) персональных получателей
  **этого** урока с `student_user_id`, безопасным display name/username, access flags;
  student видит только себя, owner teacher/admin — разрешённых recipients, в т.ч.
  доступную историю. Нельзя подставлять текущий список участников курса вместо
  lesson grants; multi-recipient legacy отображать read-only, не выбирать первого.
- Course/Lesson response: `access_mode/read_only_reason` + action-specific
  `can_manage` и `can_create_lesson` для курса; список recipients не дублировать во
  всех lessons, но display summary получателя допускается scoped batch join.
- LectureResponse additive `lesson_id/course_id/student_user_id`, `course_name`,
  `lesson_title`, `file` descriptor; `/lectures/my` добавить `course_id/view` и
  стабильный date/id sort с count. GET `/lectures/{lecture_id}` — scoped detail
  для прямого просмотра. Существующий GET/DELETE file query сохраняется.
- File descriptor для учебных материалов/ответов: `id` (доменный file id),
  `download_url` относительный, `mime_type`, `size_bytes?`, `display_name`.
  Без asset key/local path. Legacy неизвестный размер null, не 0. URL обязан
  включить требуемые query homework_id/lesson_id/student_user_id и пройти тот же
  T06/T07/T11 access; Content-Type download response окончательный.
- ReviewQueue context уже содержит course/lesson/student/homework; использовать
  новый homework detail для условия, не копировать полную модель в очередь.
- Optional `expected_updated_at` в PATCH course/lesson: exact UTC timestamp
  предыдущего DTO, проверять под parent/row lock **до** write; mismatch409, данные
  сохранены. Поле не писать в ORM values. При omission старый bearer клиент
  сохраняет поведение; SPA всегда передаёт. Archive/create/delete не выдавать за
  versioned операции. Условие и write атомарны, timestamp обновляется сервером.

Порядок: безопасные scoped context helpers → DTO/routes (static до dynamic) →
debt/lecture read → conditional PATCH. Capabilities вычислять из действующих
permission predicates и состояния, без fake write/recalculate/commit на GET.
Не вычислять права в браузере по одному is_deleted; не ослаблять guards ради флагов.

Приёмка: каждую direct URL можно открыть без ранее загруженного списка; unseen
Homework/Lecture404; ended/gap и debt file доступы совпадают с текущим контрактом;
student не получает другого recipient/contact; admin может читать исторические
материалы без student impersonation. GET не изменяет БД/уведомления.
Conditional PATCH две независимые sessions: ровно один save и второй 409;
null/nullable/course patch regressions T13R остаются.

Проверки: scoped modules/check_permission tests + source OpenAPI DTO leak scan;
full guarded pytest после завершения; diff check. При индексе/схеме Alembic
autogenerate + clean/prior-state/check; без schema change не делать пустую migration.
Риск N+1: batch context загрузка на page20/50, test query count/inspect SQL; не
перебирать все уроки для одного файла. Ручная приёмка: не требуется до UI.
Следующее T14c; результат/команды записать здесь и в STATUS/SESSION_LOG.


## Реализация 16.10.2026

Разрешена владельцем только локальная T14b; T14c не начиналась. Исходные
незакоммиченные T14a/planning/rules_project изменения сохранены. UI/DESIGN,
бинарное хранение, нормализация, правила попыток и write authorization сохранены.

- `check_permission/models_dto.py`, `read_context.py`, `repository.py`: общие
  read-only action flags и причины; batch context по конкретным lesson grants,
  без write/recalculate/lock на чтении. Admin читает историю своей ролью;
  активное доменное состояние не объявляется архивом из-за роли.
- `homeworks/{models_dto,repository,service,views}.py`: scoped direct detail,
  origin/course/teacher/student/working answer context, последняя видимая placement;
  список урока сохраняет placement своего урока. `/my/page` и legacy array
  сохранены. `/available-debts` считает SQL scope до LIMIT, исключает checked,
  учитывает порядок текущей placement и отмечает уже добавленный debt; submitted
  остаётся submitted («На проверке» в будущем UI). POST debts остаётся финальным guard.
- `lesson_students/{repository,service,views}.py`: новый scoped GET page20/offset,
  только получатели конкретного урока, safe name/username, без contact/internal PK.
  Student видит себя; legacy multi-recipient выдаёт read-only и не выбирает первого.
- `courses`, `lessons`: access/reason/action flags в detail/list; optional aware
  `expected_updated_at` только у PATCH. Проверка exact timestamp под parent/row lock,
  исключение из ORM values, stale409 без изменения данных; rollback освобождает
  блокировки course при ошибке. Сервер обновляет timestamp через clock_timestamp.
  Операции create/archive/delete не объявлены versioned.
- `lectures/{models_dto,repository,service,views}.py`: scoped direct detail,
  batch context/file, `/my` course/view, sort date+id и snapshot COUNT/page.
- `files/{models_dto,repository,service}.py`, `homework_submissions/{models_dto,service}.py`:
  metadata descriptor с domain file id, относительным авторизованным URL,
  MIME/size/display name; legacy size=null, без key/path. Для ДЗ URL использует
  видимую placement. Ответы содержат descriptor каждого разрешённого файла.
- `base/{exception,versioning}.py`, `api/exception_handler.py`: отдельный stale409.
- `tests/modules/homeworks/test_t14b_context.py`: ASGI/PostgreSQL матрица direct
  URL/roles/history/gap/revoked/download, GET SQL no-write/no-lock, recipients,
  debts/status/placement, page count/sort, actual PDF/WebP metadata, flags,
  independent sessions PATCH race, OpenAPI leaks и batch query bound20/50.
