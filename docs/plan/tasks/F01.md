## Общие инварианты и отчёт каждого этапа

- Sender contact, child recipient, parent grant, linked User, message permission
  и роль платформы различны. Никакого auth по raw ID/имени/выбору teacher.
- Confirmed Booking сохраняется при недоставке. Одна operation/receipt, один
  Lesson после materialization, один reminder; повтор HTTP не повторяет бронь.
- Один source-of-write на teacher+конкретный период; API failure не включает
  Sheets fallback. Внутренние commit-сервисы не вызывать как «одну транзакцию».
- Два teacher/shared student/другой ученик, foreign IDs, pending/revoke/архив/
  inactive обязательны; новое подключение к второму teacher только admin.
- Synthetic DB/media/JSON/clock/HTTP transport вне retained preview; preflight
  фактических DB/engine/session/role/media до тестов. MODE=TEST недостаточно.
  Новая DB — отдельное разрешённое действие этапа, не применять fixtures к existing.
- До P01 только synthetic. Ни fixtures, ни HTTP traces не содержат production ПД/
  ключей/ID таблиц, ответы/фото/ДЗ58 не используются. No network по умолчанию.
- В каждом этапе: текущие owners/схема/инварианты → scoped meaningful checks →
  self review diff → ручная приёмка где указана → карточка: paths/команды/PASS/
  FAIL/NOT RUN/остаток; STATUS коротко, SESSION_LOG3–6 строк. Не скрывать failed
  run последующим PASS; commit/push/deploy отдельно. Исправления относятся к scope.
