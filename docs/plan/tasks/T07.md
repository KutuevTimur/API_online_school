## D02 — принято владельцем 15.10.2026

- Открепление от курса или окончание срока доступа сохраняет ученику чтение и
  скачивание его персональной истории до границы доступа (cutoff). Новые занятия
  и материалы после этой границы не выдаются; отправка и правка решений запрещены.
- Преподаватель сохраняет чтение своей истории; окончание связи с одним teacher
  не отключает аккаунт ученика и не затрагивает другого teacher.
- Архив курса/урока сохраняет зависимости и файлы. В архиве запрещены изменения
  расписания, материалов, ДЗ, ответов и проверок; чтение/скачивание сохраняются.
- Восстановление курса/урока — только admin. Восстановление курса не восстанавливает
  отдельно архивированные уроки и не зачисляет автоматически откреплённых учеников.
- Повторное зачисление возвращает участие, но не открывает чужие персональные записи.
  Отдельный отзыв чтения истории — явное действие admin с аудитом.
- Безвозвратное удаление — только целого курса, только admin, отдельное действие
  с подтверждением курса и аудитом. Отдельный purge урока не входит в MVP.

Польза: история и скачивания сохраняются без доступа к продолжению обучения.
Компромисс: после открепления нельзя дописать или проверить работу в этой истории;
для продолжения нужно восстановить участие/снять архив через разрешённый workflow.
Решение зафиксировано в DECISIONS/PRODUCT/A04; реализация и результаты проверок ниже.

4. Реализовать отдельный admin purge курса: транзакционное удаление цепочки +

   защита общих объектов. Использовать PathsConfig, не удалять каталог вслепую.
5. Миграция через Alembic autogenerate с проверкой clean/prior-state/round-trip;
   backfill не должен случайно расширить доступ или потерять историю.

## Критерии приёмки и проверки

- Архивирование курса/урока не удаляет зависимые строки/файлы; восстановление курса
  не оживляет отдельно архивированный урок; повторные archive/restore безопасны.
- В архиве читаются/скачиваются разрешённые данные; все учебные writes закрыты,
  включая прямые IDs, legacy aliases, файлы и проверку ответа.
- До/на/после cutoff, expiry, позднее добавление в старый урок, повторное зачисление,
  list/count/detail/download согласованы; чужой LessonStudent никогда не открывается.
- Два teacher и общий student: открепление/архив одного не меняют второго.
- Purge доступен только admin; неверное подтверждение не меняет данные.
  Rollback не удаляет файлы; очередь переживает ошибку/restart; повтор безопасен;
  общие и чужие объекты не удаляются. Аудит сохраняется после удаления target.
- Guarded lgg-test: целевые regressions, полный pytest, migration suite,
  upgrade head/check и git diff --check. Фактические результаты приведены ниже.

## Endpoint → policy перед реализацией

| Действие | Политика T07 |
|---|---|
| DELETE course / lesson | Teacher владелец; архив с сохранением зависимостей, повтор безопасен |
| Учебные PATCH/POST/DELETE и avatar aliases | Архив предка запрещает write; работа с recipient дополнительно требует действующего участия |
| Student list/detail/download, my-materials, nested files | Свой LessonStudent + членство, публикация до cutoff и вне перерыва участия; revoked закрывает чтение |
| Teacher/admin read | Сохраняется scope T06; teacher читает свою историю |
| POST course/lesson restore | Только admin; без автоматического восстановления дочерних архивов/зачислений |
| PATCH history-access | Только admin, явный отзыв/возврат чтения, audit |
| POST course purge | Только admin, совпадение ID и имени; DB chain + outbox атомарно |
| POST admin/file-deletions/retry | Только admin; повтор очистки после commit, проверка оставшихся ссылок и PathsConfig |

Cutoff включителен по created_at персонального grant и материала (не scheduled_at).
Граница — наиболее ранняя из expires_at/access_ended_at/deleted_at; после повторного
зачисления закрытый интервал сохраняется в enrollment_gaps. Старые персональные
grant не превращаются в доступ к чужому LessonStudent.


## Реализация T07 — 15.10.2026

- Lesson soft archive вместо physical DELETE, флаги в DTO. Course archive сохраняет
  slug для restore; повторный archive идемпотентен. Удаление LessonStudent теперь
  завершает доступ без удаления материалов/ответов. Legacy course hard-delete закрыт.
- SQL scopes до pagination/count: StudentCourse history_revoked, expires_at,
  access_ended_at/deleted_at; личный grant, материал, submission и file created_at
  проверяются по cutoff включительно. My-materials и lesson flags используют те же
  границы; direct file IDs и nested JSON не обходят policy.
- EnrollmentGap хранит закрытые перерывы после re-enroll и восстановления
  teacher_students. Окончание связи не отключает User и не затрагивает другого
  teacher. Персональные grant остаются обязательны. Отсутствие StudentCourse
  больше не открывает dangling LessonStudent; отдельная negative regression.
- Общие write checks блокируют архив предков и завершённое участие, включая
  расписание исторического урока, файлы и проверку ответа. Course→Lesson→membership
  locks сериализуют образовательные writes и archive/purge; queued-write regression
  использует две независимые AsyncSession.
- Новый course_lifecycle module: admin restore без каскадного оживления, явный
  history-access, purge с подтверждением ID+имени, audit actor/action/result/target/time/
  correlation (без FK на удалённую цель), durable file_deletions queue и admin retry.
- Purge удаляет цепочку child-first и создаёт очередь в одной транзакции. Только
  после commit unlink отдельных файлов внутри разрешённых PathsConfig roots; нет
  rmtree. Ссылки из оставшихся course/student/teacher/material/file записей защищают
  общий объект. Ошибки и restart сохраняют очередь; повтор безопасен, включая
  прерывание после domain commit до worker. Небезопасный путь/симлинк не удаляется.
- Миграция 811d7911d0b4 сгенерирована autogenerate на lgg-test и дополнена
  backfill/defaults/refusal guards. Lesson archive/history_revoked по умолчанию false;
  legacy cutoff — deleted_at или updated_at. Duplicate memberships и dangling
  personal grants требуют явной сверки до DDL; небезопасный downgrade запрещён.
- README содержит контракт admin API и retry/ошибки после commit. Отдельного
  фонового scheduler нет: worker запускается после purge и через admin retry.
