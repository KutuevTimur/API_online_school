## Поведение

1. Admin-only GET `/admin/users?role=&is_active=&is_activated=&q=&limit=20&offset=0`:
   page; q по username/имени/фамилии, SQL scoped до count, case-insensitive;
   escaped wildcard, q1..100, параметры bounded. GET `/admin/users/{user_id}`:
   safe profile + `user_id,role,is_active,is_activated,created_at`. Ни hash,
   auth_version, refresh digest, ни invite token не попадают в DTO/logs.
   Обычные UserResponse/MinimalProfile не расширять admin state вслепую.
2. `/users/students` teacher: optional q, active link scope прежний; ended связи
   не превращать в общий каталог. Список бывших — через свои курсы/архив, не чужие профили.
3. Admin GET `/teacher_students?teacher_user_id=&student_user_id=&active=&limit=20&offset=0`:
   page безопасных пар, display names, active/ended_at. Teacher не получает этот
   глобальный каталог. Existing POST link/relink сохранить.
4. Admin DELETE `/teacher_students/{teacher_user_id}/{student_user_id}` завершает
   связь идемпотентно: course locks по id → link/enrollment locks как существующий
   relink; ended_at один раз, recalc deadlines в той же transaction, audit action
   teacher_student_end. Никакого User.is_active=false, каскадного удаления или
   завершения связи с другим teacher. D02 read history до cutoff сохраняется;
   повторный POST relink использует существующие gaps, не открывает скрытый период.
5. После account-status UI перечитывает admin detail, т.к. старый response не
   содержит is_active. Reset/invite issue null link сохраняет generic семантику;
   UI показывает «Ссылка не выдана, проверьте состояние аккаунта», без выдуманного
   токена/пароля. Учебную роль admin в teacher самовольно не превращать.

Приёмка/тесты: teacher/student403 на admin list/detail/end; admin pagination/q
до count, inactive/unactivated видны admin; no nested leaks; общей student связи
двух teacher независимы. End/relink/submit/lesson move concurrency с тем же lock
порядком, rollback не оставляет audit/recalc; repeated end не сдвигает cutoff;
неизвестная пара 404. End не очищает файлы. Полный scoped + guarded full pytest,
OpenAPI leak scan и diff check. Migration только если индекс нужен и обоснован.

Риски: ошибочный global deactivate, reopening gaps, deadlock. Не реализовывать
биллинг/организации/новую role систему. Ручная приёмка: не требуется, UI T15c.
Следующее T14d. Выполнение и команды записать по факту.
