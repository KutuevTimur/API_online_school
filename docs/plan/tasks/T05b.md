# T05b — одноразовые приглашения и восстановление доступа

Статус: DONE (15.10.2026). Зависимости: T05 DONE, D01 принят 15.10.2026.
Владелец поручил локальную реализацию 15.10.2026 без commit/push/deploy. Согласованный контракт — D01 в
[DECISIONS](../DECISIONS.md); ограничения общего профиля применяются в T06.

## Объём

- Заменить выдачу пароля при создании аккаунта на приглашение; пароль задаёт
  получатель. Разделить ожидание активации и административное отключение:
  приглашение/reset не должны обходить отключение аккаунта.
- Username login, nullable email с сохранением существующих значений.
  Перед сменой login проверить коллизии и совместимость текущих маршрутов.
- Приглашение 72 часа, reset 1 час, одноразовое атомарное потребление;
  хранить только digest, raw secret возвращать при выдаче один раз, не логировать.
  Новая ссылка отменяет предыдущую того же назначения.
- Teacher приглашает только своего неактивированного ученика; admin создаёт
  student/teacher и выдаёт reset активированным аккаунтам. Без SMTP.
- Reset/смена пароля отзывает refresh и повышает auth_version атомарно;
  self-change требует текущий пароль. Не оставлять legacy обходные маршруты.
- Rate limit login/reset/activation, одинаковые ответы для несуществующего
  аккаунта; аудит чувствительных admin действий без паролей/секретов.

Файлы: auth/*, users/*, новый account_invitations/*, DI/router/db_models,
Alembic migration, тесты, документация. SQL в repository, транзакции в service.
Фактические endpoint/DTO и ограничения rate limit описаны в README и результате ниже.
UI ссылки — T14; T05b проверяет backend API на synthetic данных.

## Критерии приёмки

- [x] Создание/активация ученика и преподавателя, вход по username без email.
- [x] Старые email сохранены, коллизии проверены, clean/prior-state migrations
      и metadata diff проходят.
- [x] Expired/used/replaced/wrong-purpose token отвергается; две независимые
      AsyncSession дают максимум одно успешное потребление; rollback целостен.
- [x] Teacher не сбрасывает активированный/чужой аккаунт, admin reset работает;
      токен привязан к конкретному аккаунту и назначению.
- [x] Неактивированный/отключённый аккаунт не входит; reset не снимает отключение.
- [x] После password change/reset старые access/refresh недействительны;
      чужие сессии сохраняются; self-change без текущего пароля запрещён.
- [x] Rate limits и неразглашение существования аккаунта проверены;
      digest/hash не раскрываются; raw secret только в ответе выдачи, не в логах/audit.
- [x] Полный pytest на guarded lgg-test, migration suite, upgrade/check,
      git diff --check; результаты и ограничения записаны в карточку/STATUS.
