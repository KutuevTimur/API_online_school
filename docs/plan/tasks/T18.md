## T18.1 — согласованная копия БД и файлов, доказанный restore

Перед кодом утвердить с владельцем RPO≤24h/RTO≤4h как рекомендуемые стартовые цели
и backup schedule7daily/4weekly как технический кандидат, согласовать с P01 сроками.
Выбрать фактический РФ backup destination вне VPS после D09; до него synthetic
rehearsal разрешён локально и не выдаётся за production backup.
Backup job: maintenance/write pause либо доказанная consistent схема с immutable
keys и остановленным GC; dump revision + media manifest hashes + deletion ledger,
encrypted transport/storage, least privilege, атомарная отметка success после
проверки всей копии. Secrets/encryption keys не вместе с публичным runbook.
Не считать PostgreSQL-only dump полной копией платформы.

Restore только отдельный новый target с guard, не поверх dev/prod: schema/data,
objects/hash/reference count, apply deletion ledger до открытия пользователям,
upgrade/preflight совместимого image, login2 teachers/shared student, PDF/photo/
archive/review read. При missing/corrupt file fail closed и отчёт; backup failures
не удаляют последнюю хорошую копию. Измерить actual RPO/RTO/space и испытать
failed upload/GC при backup, уничтожение reference/course, восстановление ledger.
Риски: unsynced DB/media, GC удалил referenced file, restore оживил удалённые ПД.
Приёмка: протокол rehearsal с датой/SHA/revision/file counts/duration, повторяемая
команда и rollback; месячный rehearsal/manual dispatch, не обещание без запуска.
Ручная приёмка: владелец открывает **restore stand**, скачивает прежний synthetic
PDF/фото и проверяет архив; агент сам измеряет hash/time/изоляцию.
