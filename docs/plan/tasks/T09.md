## Контракт

- Один рабочий ответ на персональное ДЗ. Старые попытки и номера сохраняются;
  при миграции рабочей становится последняя по attempt_number/id, остальные
  доступны только для чтения. Checked не открывает новую пересдачу.
- POST создаёт draft, submitted_at=null; повторное создание при существующем
  рабочем ответе возвращает 409 с требованием открыть существующий ответ.
  Номер следующей попытки вычисляется только под блокировкой родительского ДЗ.
  Partial unique index дополнительно защищает единственность рабочего ответа.
- Явный POST /submissions/{id}/submit: текст после strip или готовое вложение
  обязательны; draft→submitted с UTC submitted_at; повтор submit идемпотентен.
  Дедлайн не блокирует отправку. Submitted можно править до проверки.
- version начинается с 1 и увеличивается при изменении содержимого/состояния.
  Опциональный expected_version при правке защищает от устаревшего клиента (409).
  Все записи блокируют ответ; teacher update также участвует в блокировке.
- PATCH student добавляет файлы, сохраняя прежние ID/байты; отсутствие текста
  не очищает его. DELETE конкретного file_id и PUT конкретного file_id с новым
  файлом — явные операции. Замена сохраняет старое до успешного commit.
  Последнее содержимое submitted нельзя удалить до пустого ответа.
- Checked: запрет текста, append/delete/swap вложений, удаления ответа и
  teacher повторной правки. Исторические нерабочие попытки неизменяемы.
- Объектные права, archive/cutoff/read-only применяются ко всем новым маршрутам;
  чужой homework/submission/file ID не раскрывается. Внешние пути не выдаются.
- Уникальные серверные имена предотвращают overwrite при одинаковом filename.
  При ошибке откатывается БД, удаляются только новые файлы текущей операции;
  удаление старых ставится в durable FileDeletion в той же транзакции.
  Конвертер сохраняется; полный storage contract/автоматический worker — T12.

## Выполненное и ограничения

Добавлены is_working/version и partial unique index; migration `8a575436b7db`
сгенерирована autogenerate на guarded lgg-test, дополнена backfill и запретом
небезопасного downgrade. Родительские блокировки Course→Lesson→Enrollment→Homework
и строка ответа сериализуют создание, submit, student edit, teacher update и delete;
старый max+1 теперь выполняется под блокировкой. SQL остаётся в repository,
транзакция/DTO/rollback — service, views только передают параметры.

Имена новых файлов UUID, пользовательское имя сохраняется в metadata. Append не
удаляет старое. Point delete/swap удаляет запись и создаёт FileDeletion атомарно;
старые байты до worker сохраняются. Ошибка операции откатывает текст/version/
файловые записи и убирает только новые файлы. Конвертер не переписан.

T10 пока не выполнена: обязательная version при проверке, очередь и D05/integer
оценка остаются следующим этапом. Существующий teacher endpoint теперь блокирует
ту же строку и не может проверять draft/менять checked или историю, чтобы не
обходить T09. Он ещё не реализует полный review contract T10.

T12 остаётся: лимиты/сжатие, storage adapter, автоматическое обслуживание cleanup,
reconciliation orphan uploads после crash/ошибки удаления нового файла при rollback.
Текущий durable cleanup использует уже существующий admin retry и проверяет shared
references/PathsConfig. Обязательной ручной приёмки backend нет. Frontend/UI/E2E,
нагрузка, production/backup restore не проверялись; неизвестная БД не затронута.

Дополнительный boundary regression: после re-enroll скрытые файлы периода
отсутствия доступа не раскрываются в ответах PATCH/submit и недоступны по прямому
file_id. Удаление всего ответа со скрытыми history attachments возвращает 403,
сохраняя эту историю; checked/history ограничения продолжают действовать.
