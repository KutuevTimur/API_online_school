## P02.1 — reviewable release packet (без публикации)

Проверить текущий SHA/branch/CI, image digests/frontend hash, Alembic current/head,
schema compatibility, миграции/индексы/lock risk, backup success и restore протокол,
параметры сервера/диск/порты/соседние приложения. Не reset/reinstall VPS.
Подготовить exact команды upload/pull/config/migrate/start/smoke/rollback и
безопасный список changes; если БД внешняя UNKNOWN, её inventory/backup/rehearsal
до миграции. Указать downtime/write pause, migration runner и владельца операции.
Release кандидатом может быть проверенный dev SHA; main сейчас старый шаблон,
ветку релиза/merge отдельно согласовать, не переключать на main как на готовый код.
Показать пользователю готовый пакет и короткий запрос разрешения публикации;
не просить одобрить абстрактную инфраструктуру до этой подготовки.

## P02.2 — только после явного разрешения

DNS/TLS/proxy/deploy по packet, secret ввод в защищённом интерфейсе/SSH env,
pre-migration backup, единственный migration job, start/health. Не публиковать
PostgreSQL/media, отключить DEV routes/gallery/credentials и dev docs по runbook.
Smoke: login/invite,2 teachers/shared student isolation/direct file, lesson/PDF,
3 photo upload/review, archive, notification, logout/two tabs; synthetic disposable
аккаунты на разрешённом стенде, реальные пользовательские данные не в отчёте.
Проверить реальную доставку synthetic alert и backup расписание после отдельного
разрешения выбранного канала, HTTPS renewal и restart persistence.

Acceptance: verified URL/HTTPS, release SHA/revision/digests recorded, smoke green,
нет P0/P1, rollback доказан rehearsal. При сбое остановить расширение, сохранить
копии; rollback image только schema-compatible. Destructive downgrade/live restore
с потерей новых записей требует конкретного решения владельца, не auto rescue.
Ручная приёмка обязательна: owner открывает URL с компьютера/телефона, проходит
synthetic путь и подтверждает запуск. Нужные несекретные настройки/permissions
спрашивать здесь, не в T14. Дальше P03, реальные пользователи только по допуску.

Уточнить непосредственно перед P02: актуальные Timeweb/TLS/OS инструкции, стоимость
изменяемых ресурсов, текущая revision/data volume, доступ/окно работ. Дальние команды
не объявляются точными до этого preflight. Результаты и разрешение фиксируются здесь.
