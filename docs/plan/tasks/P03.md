## Поведение и порядок

Owner передаёт приглашения лично по D01. Минимальная памятка: вход, урок/ссылка,
ДЗ/фото/отправка, проверка/результат, архив/download, связь с поддержкой.
Памятка не заменяет интуитивность. Наблюдать самостоятельные сценарии без
объяснения расположения кнопок, фиксировать где человек остановился/ошибся,
ожидаемое действие и предлагаемое исправление. Не спрашивать «всё понравилось?»
как единственную проверку. Teacher должен выдавать/проверять без Swagger/SQL;
student с телефона отличает draft/на проверке/проверено. Teacher самостоятельно
записывает из общей недели, закрепляет время по D11, переносит одну встречу с
подтверждением, находит недобор и читает недельные суммы по D12. Памятка объясняет
горизонт регулярности и что плановая стоимость не является полученной оплатой.

До старта задать окно наблюдения (рекомендуется 2 учебные недели), поддерживающего,
фактические устройства/браузеры и стоп-условия. Измерять p50/p95 upload size/time,
ошибки запросов/файлов, частоту неясных действий, очередь проверки, disk/quota,
backup age, инциденты/потери drafts. Содержимое решений в метрики не включать.
Если сетевые условия мешают порогам, фиксировать отдельно время пользователя и сети.

Acceptance: обязательные учебные маршруты пройдены, нет утечки/потери файла/
оценки/P0/P1; backup restore и реагирование работают; непонятные ключевые действия
исправлены, у каждого оставшегося дефекта priority/owner/task. Владелец явно
подтверждает расширение до 6/60; это запуск LGG MVP, не готовый SaaS для других школ.
При утечке, неверной оценке версии, потере файлов или невосстановимом доступе
приостановить новые приглашения, применить incident runbook/P01, не замалчивать.

Проверки: E2E затронутых исправлений + полный release gate при новом релизе,
реальная самостоятельная приёмка student/teacher/admin, restore/alert evidence.
Ручная проверка владельца обязательна: решение продолжить/исправить/откатить и
допуск расширения. Риск: объявить pilot success по HTTP200 без наблюдения людей.
После MVP отдельные F01 ВК/F02 банк/F03 коммерческая изоляция; переход требует
нового запроса/исследования контрактов, в этот пилот не включать.

Перед началом уточнить людей/устройства/окно/поддержку, доступные метрики и фактический
capacity budget. Планировать по наблюдению, не обещать абсолютную удобность заранее.
