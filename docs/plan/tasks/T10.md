## Контракт

- PATCH /submissions/{id}/teacher: обязательные strict integer grade 0–5 и
  expected_version >=1, необязательный teacher_comment; status только checked.
- Только submitted working answer своего teacher; parent→homework→submission locks
  общие с T09. Устаревшая version — 409; draft — 409; checked/history — 403.
- checked_at UTC, checked_by в БД teacher FK; публичный checked_by — user_id.
- GET /submissions/review-queue: только teacher, SQL owner/active predicates до
  count/pagination. limit/offset, course_id/student_user_id, старые submitted сначала,
  ID tie-break; ответ содержит текущую version, context IDs и название ДЗ.
- Архив/завершённое участие исключены из очереди, прямое review повторно проверяет
  доступ. Итог доступен student через существующие list/detail/download.
- Шкала/комментарий — D05. Повторная проверка и пересдача отсутствуют.

## Приёмка

Два teacher и общий student, чужие IDs/filters/count/empty offset, роли;
0 и 5, invalid/missing grades/version; draft/history/checked;
редактирование до review →409; concurrent edit-vs-check, check-vs-check
в независимых PostgreSQL sessions; rollback, student result, archive/cutoff.

## Границы реализации

переписывается. Все новые review API запросы требуют integer 0–5. Нового DDL

user_id; это явно отражено в OpenAPI/README, frontend ещё отсутствует.

review всё равно повторно проверяет version/доступ под lock.
