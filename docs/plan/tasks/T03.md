# T03 — публичные ответы, активность и JWT

Зависит T02. Sol default/high. Это ограниченное исправление auth без выбора invite/UI.

## Места

`users/models_dto.py`, `auth/views.py`, `auth/auth_service.py`, `auth/token_service.py`, auth exceptions/handler, `tests/modules/auth/test_views_auth.py`, users tests. Прочитать public DTO до добавления нового: повторно использовать безопасный response, если он уже есть. Внутренний UserDTO с hashed_password нужен для verify_password, его не удалять.

## Шаги

1. Для register/register_by_admin/change_password (включая скрытые aliases) задать безопасный явный response_model. Проверить все public routes с UserDTO; внутренние Depends не сериализуются автоматически.
2. Единая проверка active при login, get_current_user и refresh. Неактивный user не получает новые токены и не пользуется старым access. HTTP-контракт: 401 для недействительной авторизации, generic сообщение без раскрытия аккаунта.
3. JWT: фиксированный допустимый algorithm из trusted config; обязательные exp и sub; exp числовой и истёкший отклоняется; sub корректный положительный ID. Перехватить JWTError/TypeError/ValueError и нормализовать InvalidJWTToken; неизвестный user — тот же auth failure, не 500. Не принимать bool как числовой ID. Не log token.
4. Проверить OpenAPI public schema и фактические response JSON; nested hash тоже недопустим. Остальные поля public DTO не менять без необходимости.

## Regression matrix

- Register/student response, master route до его удаления в T05, password response/aliases: hash отсутствует, expected public fields присутствуют.
- Active valid login/access/refresh успешны; inactive и missing user запрещены.
- Expired, missing exp, missing sub, nonnumeric sub, negative/zero, wrong signature/algorithm → 401, не unhandled exception.
- Токен без exp сформировать искусственным ключом теста, не рабочим секретом.
