## Конкретный bridge

- Add POST `/auth/browser/login` (username/password form), `/refresh`, `/logout`.
  Login/refresh JSON **только** access_token/token_type (expires_in допустим из config),
  refresh только HttpOnly cookie. Старые bearer endpoints не ломать/не использовать
  из SPA; browser login использует тот же rate limiter/account activation policy.
- Cookie `lgg_refresh`: HttpOnly, SameSite=Lax, Secure=true production, Path из
  внешнего API prefix `/api/auth/browser`, Max-Age не длиннее actual token expiry,
  без Domain. Локальный HTTP Secure=false только явный DEV/TEST; production с
  insecure/missing origin config fail-fast. Для разных origin/domain не включать
  широкий CORS как обход; proxy одинаковый в dev/prod.
- Все browser cookie POST, включая login/logout: обязательный exact allowed Origin
  (scheme/host/port), custom `X-LGG-Request: browser` header, content-type allowlist;
  OPTIONS не даёт wildcard credentials. Это выбранная CSRF-защита custom header +
  строгий Origin, не имитация случайного CSRF token. Cookie GET мутаций нет.
  Missing/foreign/null Origin и simple cross-site form→403 до ротации/записи.
- Refresh вызывает существующий atomic rotate; raw secret не возвращается в JSON/
  logs/error. Logout закрывает cookie session даже при истёкшем access, проверяет
  принадлежность raw refresh существующей family, удаляет cookie с тем же Path;
  чужую family revoke не допускает. Повтор logout безопасен. Не делать logout всех
  семей вместо текущей сессии; смена пароля сохраняет существующий global revoke.
- Client access только в памяти; boot→refresh→users/me→role guard. Single-flight
  в одной вкладке + `navigator.locks` name lgg-session для **всех** cookie mutations
  между вкладками (login/refresh/logout), recheck logout generation после lock.
  Каждая вкладка под lock читает актуальную общую cookie браузером; последующая
  ротация не инвалидирует уже выданный access другой вкладки.
  BroadcastChannel сообщает logout/account change без refresh/token payload;
  можно memory/localStorage только несекретный logout generation, не ответы/токены.
  На неподдерживаемом Web Locks браузере показать «Откройте в современном браузере»,
  не запускать несериализованную ротацию и не ослаблять replay-политику.
- Один refresh на 401; повторный 401→reauth, не бесконечный loop. Изменение user_id
  очищает cache/drafts/object URLs; reauth тем же user восстанавливает memory draft.
  Retry mutation автоматически не делать при timeout/неясном commit (A12).
- Activate/reset читают fragment token в память и replaceState убирает fragment;
  purpose определяется route, подтверждение пароля локальное; backend POST consume.
  Password8..72 UTF-8 bytes, show/hide/autocomplete/paste; успех ведёт в login.
  Invalid/expired/consumed→инструкция получить новую ссылку, без утечки токена.
  Нет request-email/password-for-student формы и auto-login после activation.

Приёмка: protected direct URL после reload, три role destinations, returnTo только
внутренний allowlisted путь; open redirect исключён. Ended/inactive/reset session
даёт корректный отказ. Login форму не прятать за объяснением JWT/cookies.

Проверки: pytest auth/rate-limit/replay + full guarded suite; browser cookie flags/
Path/no refresh JSON, foreign/null/missing Origin/simple form attacks, login fixation,
два одновременных reload/401, logout-vs-refresh, network failure after rotate,
clock expiry/password reset. Network после rotate может оборвать Set-Cookie: старая
cookie replay безопасно закрывает family и требует входа, не обещать seamless recovery.
Frontend typecheck/lint/unit/build + real Chromium и WebKit mobile smoke; secrets не
в traces. Synthetic credential seed — локальный ignored файл, дать владельцу безопасно.

Ручная приёмка: вход → reload → выйти → повторный вход; activate synthetic одноразовой
ссылкой → новый пароль → вход. Передача пароля/ссылки приватно, не в Git/SESSION_LOG.
Это ещё не полный учебный сценарий. Риск высокий: при неработающих двух вкладках
этап VERIFY, не переходить к пилоту. Следующее T14f.
