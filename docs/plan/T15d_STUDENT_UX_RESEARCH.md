## Целевые экраны и состояния

### 1. PDF: документ первым

```text
[Конспект · полное имя по раскрытию] [100% ▾] [↓] [×]
────────────────────────────────────────────────────
                 страница 1
                 страница 2
                 страница 3 … обычная прокрутка
```

Одна компактная строка desktop56–64px; на360 допускаются2 строки суммарно≤104px,
без обрезания доступных имён. Icon download имеет aria-label «Скачать файл» и
tooltip на hover/focus. Полное имя доступно по фокусу/раскрытию. Счётчик страницы
можно оставить пассивной подписью, но не отдельной панелью и не live-announcement
на каждое движение scroll. Файлы выбираются с исходного списка; закрытие возвращает
к точному opener. Несколько файлов teacher остаются доступны в ReadFiles вне viewer.

Масштаб: fit width по умолчанию, browser pinch не запрещать. Один trigger «100%»
раскрывает «По ширине»,50/75/100/125/150/200/300% и компактные ±; keyboard доступен.
Жест — дополнительный, не единственный способ. Не перехватывать глобальные
Cmd/Ctrl +/- и scroll колеса, не выключать browser zoom. Внутренний zoom при
применении сохраняет относительную позицию чтения; боковой scroll допустим
только внутри документа, не у всей страницы. На desktop fit width не обязан
растягивать A4 сверх комфортного размера, но текст должен быть резким: проверить
canvas backing store/devicePixelRatio с ограничением пиксельного бюджета.

Реализация через существующий PDF.js pipeline: один document/worker на активный
просмотр; видимые страницы + ближайшие соседи, placeholder правильных размеров,
cancel/destroy/revoke на смене файла/выходе/сессии. Не монтировать100 canvas,
не конвертировать PDF в base64 и не отправлять его внешнему viewer. Сохранить
text layer; virtualisation не должна выкидывать фокус/выделение читаемой страницы.
Начать с проверки возможностей установленной версии PDF.js, не добавлять новый
viewer framework автоматически. Непрерывный scroll — presentation change,
Range API/новый backend не нужен для текущего blob-контракта. Лимит20МиБ остаётся.

Loading: шапка и область файла сохраняют геометрию, «Загружаем документ…».
Ошибка: «Не удалось открыть документ» + retry и download;403/404 не превращать
в «повреждён PDF». Отдельная ошибка страницы не скрывает остальные доступные.
Фото сохраняет contain/zoom; учебные ссылки/действия внутри PDF не включать
попутно. Native встроенный iframe не рекомендован: поведение mobile и защищённая
загрузка перестают быть единым контролируемым контрактом.

**Внешняя проверка:** [PDF.js FAQ](https://github.com/mozilla/pdf.js/wiki/Frequently-Asked-Questions#i-want-to-render-all-100-pages-in-a-document-at-a-high-resolution-is-it-a-good-idea)
описывает стоимость canvas и рекомендует рендерить видимые страницы.
[W3C Pointer Gestures](https://www.w3.org/WAI/WCAG22/Understanding/pointer-gestures.html)
требует альтернативу сложным авторским жестам. Отсюда вывод: убрать постоянный
ряд кнопок можно, убрать доступное управление масштабом целиком — нельзя.
Цели44px — контракт LGG; не выдавать это за минимальные24px WCAG2.2AA.

### 2. «Мои занятия»: самостоятельная задача, не второй календарь

```text
Мои занятия                    [Все курсы / выбранный курс ▾]
Последнее проведённое · 21 октября
Пробный вариант ЕГЭ      [Конспект] [Домашнее задание] [Открыть занятие]

История                     [2026 ▾] [Текущий месяц]
[‹]  Авг  Сен  ОКТ  Ноя  Дек  [›]       mobile:3 месяца
21 окт · Пробный вариант ЕГЭ       Проведено          [⌄]
17 окт · Параметры и графики       Проведено          [⌄]
14 окт · Параметры и графики       Проведено          [⌄]
... серверная пагинация внутри месяца, если нужна
```

Последнее — последнее completed по scheduled_at, не последнее загруженное PDF
и не просто прошедшее scheduled. Не убирать старый материал из-за отсутствия
нового. Блок компактный: padding16–20, тема20–24, метаданные14; mobile действия
переносятся, не три сжатые кнопки. Details последнего по желанию, без длинного
текста условия на старте. Последнее scoped выбранным курсом/предметом.

История: текущий месяц по умолчанию; прошедшие desc, будущий месяц asc;
в смешанном текущем месяце отдельный компактный подзаголовок «Предстоящие».
Запланировано/Завершено/Отменено подписаны; time-past не равен completed.
Открытие месяца не центрирует ленту; стрелки листают окно месяцев, не выбор.
URL хранит месяц, позицию ленты, course_id, page и раскрытый lesson.
Изменение курса/месяца сбрасывает page/expanded; Back восстанавливает контекст.
Для пустого будущего месяца — «Занятий в этом месяце пока нет» + «К расписанию».
В collapsed строке отсутствующий конспект не показывать; раскрытая строка даёт
проверенные файлы/ДЗ. Не выводить «нет» до завершения GET. Загружать attachments
только последнему/раскрытому уроку, не делать66 запросов на весь архив.

Без subject MVP фильтр честно называется «Курс», labels `name · teacher_name`.
При единственном курсе не занимать место selector: его подпись в шапке.
Предложение на согласование: после появления subject оставить «Все» default
для multi-subject, при нескольких педагогах одного предмета показывать teacher
в строке. При одном педагоге можно оставить его только в шапке.

Поиск не включать в первый пакет. На33 уроках месяцы сокращают список до8–9
и темы уже помогают найти нужное. `/lessons` не имеет search-параметра: нельзя
фильтровать только загруженную страницу и называть это поиском всей истории.
Если поиск понадобится, отдельный server search по title/topic, pagination/total,
permission scope. Не использовать filename как достоверный предмет или тему.

### 3. Занятие и ДЗ: согласованная визуальная грамматика

Верх урока: тема (fallback title), дата/время и статус, предмет/course+teacher,
«Присоединиться» при URL; не отдельный огромный блок «О занятии» для одной ссылки.
Далее Конспект → Домашнее задание → Ваше решение → Проверка учителя.
Два первых блока имеют одинаковые radius16/padding20–24 desktop/16 mobile,
но одинаковая форма не означает одинаковую фиксированную высоту.

| Подтверждённое состояние | Блок ДЗ в уроке | Блок ответа на странице ДЗ | Статус/действие |
|---|---|---|---|
| Конспект/ДЗ отсутствует | мягкий materialMissingSurface, ink, «Пока не добавлен/не выдано» | формы нет, если самого ДЗ нет | без «ошибки ученика» и без danger icon |
| ДЗ есть, server answer нет | reviewSurface / жёлтый | materialMissingSurface | «Решение ещё не отправлено»; в уроке «Подготовить решение», в форме «Отправить решение» |
| server draft | жёлтый | reviewSurface | «Черновик · не отправлен», «Продолжить решение» |
| submitted | successSurface | successSurface | отдельно заметный lesson/ink badge «На проверке», «Решение отправлено»; «Открыть решение» / «Сохранить изменения» |
| checked | successSurface | successSurface, read-only | mint/success badge «Проверено», оценка0–5; в блоке ДЗ «Посмотреть результат» |
| loading/error/unknown | нейтральная поверхность | нейтральная поверхность | загрузка/retry, не ложное отсутствие/успех |
| archive/read-only | нейтрально, причина read-only | без mutation controls | доступные файлы/результат открываются |

Конспект есть → successSurface; самостоятельный материал не зависит от статуса
ответа. Missing у будущего урока не ошибка: мягкий красный из пожелания владельца
оставить лишь тихим фоном с нейтральным текстом. Если учитель явно выбрал
«не требуется», показывать нейтральное «Не задано» только при доступном student
контракте, не выдумывать flag по отсутствию файлов.

«На проверке» предлагаю голубым, а не красным/жёлтым: ученик уже сделал свою часть,
жёлтый остаётся призывом к его действию. Badge min-height32, текст14/600, не кнопка;
checked mint с success border. Это предложение student, не изменение принятой
teacher-плашки submitted жёлтого цвета: роли требуют разных действий.

Внутри каждого ДЗ — условие/файл + status + действие. Не скрывать несколько ДЗ
под единственной кнопкой. «Подготовить решение» точнее «Отправить решение» на
переходе: клик ещё ничего не отправляет. На mobile кнопка на ширину блока44px+,
desktop по содержимому. Checked кнопка ведёт к видимому разделу результата
(anchor с переносом фокуса/без перекрытия); сам результат можно оставить ниже
по желаемому порядку, не дублируя grade в трёх местах.

ReviewResult уже поддерживает `review_files` и отдельный `ReadFiles review`.
Файл проверки необязателен; отсутствие не должно рисовать пустой viewer.
Сохранить grade0 как допустимое значение. Нет комментария → спокойное
«Учитель не добавил комментарий», без тревожного empty-state.

Форма: условие доступно до ответа; конспект компактной строкой дополнительных
материалов, особенно на mobile. Не скрывать всё условие по умолчанию.
Под формой одно основное действие; не вводить sticky bar до проверки keyboard.
Сохранить необязательный текст, multiple picker, лимиты, per-file errors,
версию и dirty guard. При submitted копию про будущую отправку заменить;
при draft объяснение немедленной загрузки файлов оставить. При ошибке/timeout
не давать зелёный фон нового успеха до подтверждения сервера.

### 4. «Мой день», расписание, списки, уведомления, профиль

Desktop главную сохранить двухколоночной; mobile изменить DOM-порядок согласованно
с визуальным и keyboard (не CSS order с неожиданным Tab). Заголовок nearest20–24,
дата18–20, padding16–20; result в2–3 строки: тема, «Проверено · 1 из5»,
«Посмотреть результат». Убрать повтор «Проверено» и демонстративно огромную цифру
оценки: это полезный итог, а не центральный показатель личности школьника.
Жёлтые todo карточки оставить; due в прошлом и placement debt различать словами,
не вычислять debt заново только по времени.

Расписание остаётся планом недели: время → тема → course/teacher → статус.
Существующий ScheduleLesson уже запрашивает Course, teacher_name можно показать
без нового API. MyDay получает только4 courses: нельзя считать эту страницу
полным справочником; query nearest.course_id нужен для отсутствующего курса,
с повторным использованием readKey/cache. Никакого teacher lookup по произвольному id.
Синяя planned метка сохраняется,55мин убрать только из обзорной карточки;
длительность продолжает участвовать в расписании/elapsed, бизнес-логику не менять.

Список ДЗ сохраняет существующие фильтры/status/pagination. Разумное точечное
улучшение: theme/title первыми, status badge, дата урока/срок вторично; default todo
оставить. «К выполнению» на карточке draft дополнить «Черновик», не обозначать
его отдельным несуществующим статусом API. Архив/Все доступны, не маскировать
read-only как пустой список.

Уведомления: default все уже работает. После разрешённого enrichment строка
«Работа проверена» + «Математика · Тимур · Параметры» + время/непрочитано.
Фильтр предмета необязательный, сбрасывает offset, влияет на total на сервере.
При удалённом/недоступном объекте контекст не должен раскрывать чужие данные;
target авторизуется повторно. Не отмечать read при просмотре списка/hover/
обогащении. Текущий PATCH происходит только по явному open — сохранить.
Профиль оставить без редизайна; основные поля и secondary disclosures достаточны.

## Данные и информационная архитектура: что возможно сейчас

| Потребность | Реальный контракт | Минимальный честный вариант |
|---|---|---|
| Учитель day/schedule | `CoursesResponseDTO.teacher_name`, Lesson.course_id | cached course read, fallback без выдуманного имени |
| Предмет | поля subject нет в проверенных DTO Course/Lesson/Homework/Lecture | показывать course.name как курс; owner может позже согласовать осмысленные названия, данные сейчас не переименовывать |
| Фильтр предмета | есть course_id, нет subject_id | course selector; не объединять курсы по догадкам/иконке |
| Последнее/месяцы | `/lessons` status/date/sort/page, topic, has_lecture/homework | student-scoped query; attachments lazy через текущие endpoints; permission runtime проверить |
| Поиск темы | topic есть, search query отсутствует | после MVP отдельный server search, либо явный ограниченный поиск в полном выбранном месяце, не обещать глобальный |
| Дата занятия у файла | Lecture.created_at/lesson_id, не scheduled_at | история от lessons, не66 joins по lecture rows |
| Контекст уведомлений | нет course_id/name/teacher, target даёт только object/homework | отдельный минимальный backend enrichment proposal, не цепочка fetch на каждую строку |
| Файлы проверки | Submission.review_files, ReviewResult умеет открывать | использовать existing, проверить реальный пример в следующей приёмке |

Два варианта IA:

1. **Рекомендованный MVP:** «Мои занятия» — основной вход в историю; «Расписание» —
   будущая неделя; «Домашние задания» — работа/результат. «Мои курсы» сохранить
   вторично (на mobile «Ещё», на desktop вторичная ссылка из истории/дня),
   direct course routes и архив не удалять. Курс пока даёт преподавателя и границу
   обучения. Не дублировать36 уроков в двух равноценных основных разделах.
2. «Предметы» как основной каталог карточек → история выбранного предмета.
   Полезно при реально нескольких направлениях, но сейчас один курс без subject
   и новый уровень навигации до нужного конспекта. Отложить до устойчивой модели.

Предметные карточки после решения: одна система Lucide (Calculator/BookOpen/Code/
Leaf), одинаковый stroke20–24, умеренный фон и текстовое название, цвет не статус.
Не привязывать subject к порядку карточки или строке имени. Если нужен настоящий
subject: отдельная минимальная задача на nullable subject/subject_id курса,
источник/редактирование teacher, backfill по явным данным и read DTO. Это изменение
модели, не косметический пакет Sol. Конкретный словарь и миграцию решить отдельно.

Общие справочники и библиотека заданий ОГЭ/ЕГЭ — **после MVP**: текущие lecture
персональны и связаны с занятием; нельзя обещать course-level библиотеку без
контракта доступа, сущностей, редактора и жизненного цикла. Она не нужна для
завершения текущего пути занятие → ответ → проверка.

## План небольших пакетов для Sol

Каждый пакет — отдельное явное поручение, локально, без commit/push/deploy.
До работы прочитать актуальные AGENTS/STATUS/карточку/rules и только свой раздел.
Не совмещать S1 с новым subject backend или визуальной концепцией.

### S1 · общий PDF viewer — первым

Файлы: `frontend/src/shared/ui/FilePreview.tsx`, соответствующий CSS module
(импорт уточнить перед правкой), `features/courses/ReadUI.tsx`, существующие
FilePreview/ReadFilesEmbedded tests. Зависимость: утвердить одну toolbar/масштаб.
Сначала continuous pages и lifecycle, затем toolbar, затем память позиции.
Не менять shared/api/files.ts transport, auth, MIME и лимиты без необходимости.

Приёмка: одно- и многостраничный PDF,20/100 страниц, длинное имя, фото, damaged/

устройстве. Download сохраняет правильный файл; только один pipeline.

Проверки:33 урока/36 включая будущие; месяц с0/1/более20 записей, декабрь→январь,
МСК границы, отмена/архив, несколько курсов/учителей, пустой/ошибочный course query,

Без нового разрешения backend этот пакет ограничен сохранением имеющегося списка
и описанием дефицита. При разрешении минимальное enrichment NotificationResponseDTO

DTO/service/repository/views, generated frontend schema, notifications/api/page/tests.

### S6 · приёмка и необязательная визуальная проба

Сначала единый read-only обход после S1–S4: day → lesson → PDF → Back;
history3 месяца → lecture/ДЗ → Back; четыре состояния ответа; profile/notifications.
Один компактный набор1340/768/360, затем только проверки исправленных дефектов.
Для UI изменений Sol выполняет scoped unit/component, types/lint/format,
API-types/tokens и build по текущим scripts, mandatory premium/Impeccable gates
после готовности; не запускать DB suite ради цвета. Все PASS/NOT RUN записать.
Отдельно ручная приёмка владельца, без галочки от агента. Shared viewer требует
teacher regression; admin проверяется лишь если изменены shared tokens/shell.

## Решения для владельца и ограничения

Рекомендуется согласовать один набор: **S1 PDF toolbar+scroll → S2 «Мои занятия»
с временным фильтром курса и «Все» при нескольких → S3 голубой «На проверке» на

## Визуальное направление — на согласование после плана student

**«Светлый рабочий стол»**: теплота вокруг учебного материала, спокойный документ
в центре. Сохранить Manrope, ink, голубой, мяту и жёлтые действия. Отличительная
деталь — компактная дата как край учебной страницы и ясный ритм «урок → работа →
результат», без декоративных процентов/маскотов/случайных иконок.

Предложение палитры, ещё не tokens: основной canvas #F4F9FB, локальный тёплый
отсвет #FFF9EE, поверхность #FFFFFF, ink #193E51, голубой #C8EBFC, мята #C8F0DB.
Жёлтый action #FFE7A3 и остальные статусные цвета остаются текущими.
На student overview — очень слабое статичное radial пятно тепла сверху справа,
затухающее к привычному canvas; никаких gradients под текстом/form поля и PDF.
Панели держать преимущественно плоскими, одна мягкая тень только у ближайшего
урока/поднятого документа; не shadow на каждой строке. Border/radius16 прежние.
Это осознанное исключение из текущего DESIGN «без gradient», поэтому только
после согласования отдельного student-scoped варианта, не тихая смена theme.

Типографика: page heading32–40/750, тема20–24/650, основной16, метаданные14;
меньше конкурирующих h2, больше содержательных тем и дат. Не вводить второй font
ради дороговизны. Desktop gap24, mobile16, строки истории компактные72–88px
при обычном контенте, длинные темы растут без ellipsis важных данных.
Интерактивные цели44px; одинаковые статусы имеют одинаковую насыщенность.

Три применения:

1. **Мой день:** мягкий тёплый свет на фоне, ближайшая голубая карточка с крупной
   датой и маленькой Video-иконкой; жёлтые задачи — активный центр, результат
   спокойной мятной строкой. На mobile убрать декор, если мешает плотности.
2. **Мои занятия:** белая история как лист с тонкими разделителями; дата слева,
   тема в центре; selected month голубой. Последнее занятие — узкая мятная
   полоса с файлами, не огромная hero. Тёплый фон виден между блоками.
3. **PDF:** нейтральный светло-серый стол, белые страницы с едва заметным краем,
   toolbar визуально тише документа. Учебный PDF не перекрашивать и не декорировать.

Не переносить новый canvas/shadow глобально на teacher/admin: там уже приняты
плотность и цветовые значения. Shared viewer меняется для обеих ролей по S1,
но оттенки student overview scoped. Общие theme tokens менять лишь после
сравнения day/history/form student с teacher day/review и admin tables; контраст
измерить заново. Без смены глобального radius/font/shell и без анимации бликов.
Первой визуальной приёмкой достаточно двух вариантов одного student day,
а не moodboard всего продукта. Критерий: теплее и собраннее при сохранении
быстрого доступа к делу; фон не должен соперничать с жёлтым заданием.
