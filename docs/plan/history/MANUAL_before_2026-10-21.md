## 3. Преподаватель: короткий маршрут T15b.1

1. Войти `teacher` → «Ученики». Проверить имя/фамилию, отдельный числовой класс и
   вторичный логин. Поиск/класс/4 сортировки меняют весь server результат, не страницу.
2. Открыть ученика с материалами по актуальному helper. Сразу видно основное
   персональное пространство и занятия; не требуется выбирать курс/зачислять вручную.
3. Раскрыть материалы занятия, открыть PDF, закрыть Escape, проверить возврат фокуса.
4. Открыть второстепенные настройки: общий класс, описание/ссылка встречи курса,
   приглашение. Legacy курсы не исчезают и не сливаются с основным.
5. У нового synthetic ученика «Начать занятия» создаёт одно пространство. После
   reload/повтора не появляется копия. Создание ученика и приглашение меняют DB;
   не используйте настоящие имена/почту. Ссылку активации открыть отдельно.
6. Архив/открепление — только после чтения подтверждения. История и protected
   download остаются read-only; другие преподаватели общего ученика не затрагиваются.
7. Повторить список/ученика на360px и клавиатурой; возврат сохраняет безопасные
   sort/filter/page. Личный текст поиска не пишется в URL.

Это не маршрут выдачи материалов: standard teacher lesson editor, напоминания без
ДЗ/конспекта и «Мой день» запланированы дальше. Недельные группы истории — предложение.

## 4. Ученик: чтение и материалы

1. `read_student` → «Мой день» → активная алгебра → занятие «Квадратные уравнения».
   Время МСК, длительность и backend состояние различимы. Встреча есть только если
   настроена настоящая http(s) ссылка; отсутствие не заменяется пустой кнопкой.
2. Открыть «Учебный пример.pdf»: вторая страница/zoom/download, затем Escape и
   возврат фокуса. Скачивание не создаёт решение. Фото — contain/масштаб/листать.
3. Расписание: неделя/дни/пустой день/возврат в курс. «Уже прошло» — подпись по
   времени, не автоматический completed. Подписи недель и отметки дней — TODO T16.1.
4. Курсы→архив: материалы читаются/скачиваются, write controls отсутствуют.
5. `profile_student` → конспекты: фильтр курса, даты, архив, detail/PDF; в свежем
   наборе3 записи. Внутри уроков4 PDF, включая архив; у геометрии может быть пусто.
6. Уведомления: открыть недоступное → понятное сообщение и прочтение; открыть ДЗ
   → direct homework; «Только непрочитанные», Space и reload сохраняют фильтр.
7. Профиль: изменить synthetic имя/логин, сохранить/reload, avatar заменить/удалить.
   Для смены пароля использовать отдельный password_student и свой новый пароль;
   старые sessions отзываются. Admin avatar-профиль не обещан.

Набор synthetic: у каждого учебного ученика два преподавателя и архив, три курса,
семь занятий/ДЗ. Точные ID — `student_read` / `student_answer` / `student_profile`
в текущем JSON. Названия повторяются в разных независимых мирах, это разные записи.
Completed/cancelled и проверенные0/5 подготовлены fixture. Даты относительные к seed,
не переносите старую неделю/время из журнала в текущий маршрут.

## 5. Решение ученика: подробный проход T15a.2

Войти `answer_student`. В «Домашках» выбрать непроверенное задание алгебры
«Квадратные уравнения», условие x²−5x+6=0. Не начинать с fixture checked.

| Действие | Ожидаемый результат |
|---|---|
| Набрать synthetic текст и выбрать3 synthetic фото | До сохранения — память вкладки/очередь, не submitted |
| Попытаться уйти; отменить уход | Текст/выбор сохранены, диалог понятен |
| Сохранить черновик, затем reload | Тот же server draft и3 файла; не «На проверке» |
| Добавить4-е фото, сохранить | Первые3 не теряются |
| Удалить один файл с подтверждением | Удалён только выбранный, осталось3 |
| Заменить одно фото | Соседние сохранены, читаемость не как у avatar512 |
| Отправить решение | Сначала save/files, затем submitted «На проверке», одна работа |
| Открыть через фильтр submitted, reload | Текст/3 файла/статус сохранены |
| Дополнить текст и сохранить изменения | Тот же submitted, без второго ответа/уведомления |
| Открыть fixture checked0/5 | Оценка/comment/read-only; это другая заранее проверенная работа |

Null deadline — «До следующего занятия», не1970. Debt/история размещения читаются,
но полноценное добавление долга teacher через UI пока не реализовано. Исторические
попытки отдельно, пустая история допустима. Проверка вашей новой отправки через
teacher UI станет доступна в T15b.3; не считать fixture завершением полного цикла.

## 6. Сохранность и ошибки

- Набор текста/выбор файла — локальные; reload/закрытие могут их потерять. Перед
  уходом должен быть guard. Отмена ухода сохраняет работу, подтверждение очищает.
- Server draft/submitted/checked переживают reload и выход. Выход/другой user
  очищают memory drafts и private preview URLs, не server решение.
- Cancel upload не доказывает rollback: сервер мог записать. Unknown result →
  сначала перечитать состояние; auto retry записи без проверки не допускается.
- Ошибка/version409 сохраняет локальный текст; сравнить актуальную версию. При
  неудачном GET повтор записи остаётся заблокированным, успех не выдумывается.
- После checked текст/файлы/grade/comment неизменяемы. Архив закрывает любые
  учебные writes; отмена встречи сама не удаляет материалы.
- Для ошибки доступа/удалённого target есть сообщение и возврат, без redirect loop.
- Offline/online/две вкладки/zoom200% — дополнительные ручные сценарии ниже,
  а не уже выполненные проверки чекапа.

## 9. Как сообщать замечания

Для каждого замечания отдельный короткий блок:

```text
URL: (адрес страницы, без токенов и приватного fragment)
Роль / ключ аккаунта: student / answer_student (без username/пароля)
Устройство: desktop или360px; браузер; масштаб
Что сделал: 1… 2… 3…
Что ожидал:
Что получилось: точная подпись/статус, какие данные остались или исчезли
Повторяется: всегда / иногда / один раз
Скриншот: приложить экран без файла входа, паролей и приватных ссылок
```

Можно отдельно написать «непонятно, что нажать» или «визуально не нравится» — это тоже результат приёмки. Не нужно самостоятельно диагностировать API. Отметки в чек-листе ставите вы; замечания не означают автоматического разрешения на исправления или следующий этап.
