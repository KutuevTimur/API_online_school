## Overview

Operate: школьники 13–18 с телефона отправляют фото, teacher преимущественно с
компьютера выдаёт задания/проверяет; основные действия teacher нужны и на телефоне.
Русский интерфейс ru-RU, время Europe/Moscow, видимая подпись МСК.
Спокойный светлый кабинет с характером. Узнаваемый приём — последовательность
занятие → ДЗ → проверка: читаемые даты/время, разные поверхности для будущего
занятия и результата, понятное следующее действие. Не превращать в социальную ленту.

История выбора сохранена в SESSION_LOG; прежние варианты не конкурируют с
актуальными двумя references. Не запускать повторное продуктовое интервью.

## Простота как критерий MVP · 20.10.2026

Понятность для ученика и учителя обязательна уже в MVP. Экран отвечает на три
вопроса: где моя работа, в каком она состоянии, что делать дальше. Главное действие
одно и заметно; вторичные настройки раскрываются по необходимости. Дубли, технические
пояснения и бесполезные показатели не занимают основное место. Цвет выделяет смысл,
а не украшает каждую строку: голубой — действие/выбор, мята — успех/результат,
красный — ошибка или требующее внимания отсутствие. Всегда есть текстовая подпись.
Сохранять принятую основу, контраст, клавиатуру и удобство на телефоне. Проверять
сквозной путь обеих ролей с реальным API; работа одной стороны не равна готовому UX.
Не превращать локальное упрощение в бесконечный редизайн или добавление функций.

## Colors

Стартовые tokens — frontmatter. Голубой primary — основные действия, lesson —
занятие и область ответа; mint — результат и подтверждение. Активная верхняя
навигация светло-голубая. Карточки могут иметь мягкие голубые/мятные поверхности,
как в принятом примере; без разноцветного оформления каждого объекта.
Долг — подписанный тёплый amber, danger — ошибки/опасные последствия.
Статус всегда подписан словами, оценка — числом, не одним цветом.

Владелец принимал макеты, не HEX по отдельности. T14d измеряет контраст; минимальные
коррекции для WCAG допускаются с записью причины, без нового редизайна.
Dark theme не входит в MVP. Forced-colors поддержать системными цветами.

## Typography

Manrope variable, локально размещённые Latin/Cyrillic WOFF2 из Fontsource5.3.0,
OFL-1.1 сохранить; никаких Google Fonts запросов от реальных пользователей.
Body16, служебные подписи 14, основной заголовок 32–40 mobile/40 desktop;
отдельные короткие greeting headings до 48 допустимы без вытеснения рабочих данных.
Вес 400/500/650/750, tracking display не ниже −.04em, body normal.
В runtime увеличить мелкие подписи чат-reference до читаемых 14; его 12/11 не являются
правилом production. Имя/срок/статус никогда не обрезать без раскрытия.

## Layout

Desktop: белая верхняя навигация, main padding28–36, max content1120; small laptop padding24.
Mobile360+ padding16–20, один основной столбец, нижняя навигация и «Ещё», safe areas.
До1023px shell использует нижнюю навигацию и «Ещё»; 768px остаётся точкой проверки
контента. Верхнее меню на планшете не сжимать ради сохранения desktop вида.
У ученика просторные задания/кнопки; у teacher/admin компактные строки/таблицы,
без уменьшения body текста. Повторяющаяся карточка нужна только самостоятельному
объекту; не упаковывать каждый заголовок и подпись в отдельную рамку.

Главная: ближайшее занятие слева, задачи справа, курсы ниже; на телефоне один
столбец с ближайшим действием первым. Списки ДЗ/формы — по актуальному reference.
На проверке крупное решение слева и форма справа; narrow — последовательно.
Длинные формы скроллятся документом. Sticky actions не перекрывают клавиатуру/фокус.

## Elevation & Depth

В основном плоские поверхности: один тонкий border либо мягкая тень для overlay,
не несколько одновременно. Без glass/gradient/noise, декоративных графиков,
маскотов и выдуманных процентов успеха. Интерес создают типографика, композиция,
цвет занятия, ритм и содержательные детали.

## Shapes

Controls8, panels16, small status5–6; круглые только avatar и второстепенные icon
controls. Основные действия обязательно с текстом: стрелка в reference не должна
делать важное действие загадкой. Touch target44px независимо от размера пиктограммы.

## Components

Owner map — A13. Tokens source после T14d: `frontend/src/app/theme.ts`, CSS/Mantine
adapters получают значения из него; DESIGN хранит норму, runtime изменение требует
обновить эту норму одновременно. `app/styles.css` — global focus/scrollbar/selection,
не независимая копия палитры. Остальные CSS Modules используют variables.

Select/Date/Dialog — общие Mantine adapters, не новые компоненты на каждый экран.
Lucide единый stroke/icon system; названия ролей/состояний русские.
Button idle/hover/focus/busy/disabled; error рядом с полем, AsyncState/empty recovery,
preview zoom/download, upload progress/processing из A12. Reserve media/button
geometry; fonts и feedback не двигают действия. Reduced motion отключает необязательное.

## Do's and Don'ts

- Сначала ясность: «где я / что произошло / что дальше» видно без инструкции.
- Не называть сохранённый draft отправленным; submitted — «На проверке», checked — «Проверено».
- Основная кнопка словом; label виден постоянно; tooltip/hover не единственный способ понять.
- Не возвращать default Mantine blue theme вместо принятого направления.
- Не добавлять красоту ценой тесных форм, маленького текста и скрытых действий.
- Макет не подтверждает MIME/срок/количество страниц PDF: runtime получает их из API/файла.
- Ручная приёмка T15/P03 без подсказок: непонятное обязательное действие — дефект UI.
